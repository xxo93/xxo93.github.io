环形链表 II

给定一个链表头节点 head，返回环的入口节点；无环返回 null。 进阶：O(1) 空间。经典做法：先用快慢指针判圈，相遇后把一个指针放回 head，两个指针同步走 1 步，再次相遇即入口。

相遇后：p1 = head，p2 = 相遇点；两者每次都走 1 步 → 再次相遇 = 环入口
为什么可以这样？核心是 a = c + (k−1)·L，下面详细推导。

操作日志

一、核心问题：为什么第二次相遇就是环入口？

这道题最巧妙的地方不是快慢指针判圈（那是 141 题），而是相遇后怎么一步定位入口。先定义三段距离：

  • a：从 head 走到环入口的步数
  • b：从环入口沿 fast 方向走到第一次相遇点的步数
  • c：从相遇点沿 fast 方向继续走到环入口的步数
  • 环长 L = b + c
// 相遇时 slow 走过的路程：
Sslow = a + b
// fast 速度是 slow 的 2 倍，且 fast 在环里套了 k 圈：
Sfast = a + b + k·L
// 由 S_fast = 2 · S_slow：
2(a + b) = a + b + k·L
// 两边减 (a + b)：
a + b = k·L
// 把 b 移项，并用 L = b + c：
a = k·L − b = (k−1)·L + c
解读这个等式：a = (k−1)·L + c 的意思是——
从 head 出发走 a 步，到达环入口；
从相遇点出发走 (k−1) 整圈 + c 步，也到达环入口。
而 (k−1) 整圈 是无效位移（绕一圈回到原位），所以： 从 head 走 a 步 = 从相遇点走 c 步，两者同时、同速（每次 1 步）出发，必然在环入口相遇。

二、用示例 [3,2,0,-4] pos=1 验证

环入口是节点 1（值 2），head=3(0) → 2(1) → 0(2) → -4(3) → 回到 2(1)。

量值含义
a1head(3) → 环入口(2)
b2环入口(2) → 0 → 相遇点(-4)
c1相遇点(-4) → 环入口(2)
L3环长 = 2 + 1
k1fast 在环里套了 1 圈

代入公式：a = (k−1)·L + c = 0·3 + 1 = 1 ✓

所以：p1 从 head(3) 走 1 步到 2；p2 从相遇点(-4) 走 1 步到 2。第二步就在 2 相遇 = 环入口。

三、两阶段算法流程

  1. 阶段一：slow=fast=head，slow 走 1 步、fast 走 2 步，直到相遇（判圈）。
  2. 阶段二：把 fast（或任意一个指针）放回 head，两个指针都每次走 1 步，再次相遇即环入口。

四、带详细注释的 Python 代码

class Solution: def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]: # ===== 阶段一：快慢指针找相遇点 ===== slow = fast = head while fast and fast.next: slow = slow.next fast = fast.next.next if slow is fast: break else: return None # fast 走到 null，无环 # ===== 阶段二：同步走 1 步找环入口 ===== # slow 留在相遇点，head 从头开始；两者同速走 # 由 a = (k-1)L + c，必然在环入口相遇 while slow is not head: slow = slow.next head = head.next return slow # 相遇点 = 环入口

五、常见追问

  • k 一定是 1 吗？不一定。环很长时 fast 可能套好几圈才追上 slow，但公式 a = (k−1)L + c 依然成立——多出来的 (k−1)L 是整圈，不影响相遇位置。
  • 为什么阶段二不能继续用快慢速度？因为我们已经由数学证明 a 这段距离等于 c 这段距离，必须同速才能保证同时到达。
  • head 就是环入口（a=0）怎么办？阶段二第一次检查 slow is head 就成立，直接返回 head，正确。
  • 哈希表做法 O(n) 空间为什么不选？面试要求 O(1) 空间时必须用快慢指针；O(n) 空间的哈希表虽然简单，但不符合进阶要求。

六、复杂度

时间 O(n)：阶段一 slow 走不到一圈就相遇；阶段二走 a 步。
空间 O(1)：只用两个指针。
